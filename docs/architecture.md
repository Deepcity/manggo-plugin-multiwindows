# MultiWindows 原生集成架构

> 当前状态：原生 DLL 与进程生命周期加载器原型已实现，并完成本机匹配构建的真机验证；尚不是官方 `.mplugin` 或跨版本发行版。

## 1. 不变量

- 标题栏 `＋` 创建 Manggo 原生 `TranslationWindow`，不是外部网页或只读贴图。
- 输入、划词、截图入口在最终显示分发前改为新窗口，不能覆盖原窗口草稿或译文。
- 每个窗口使用自己的原生控件、请求对象和 `TranslationRun`，不使用全局单例会话模拟多窗口。
- 翻译走 Manggo 原生管线，复用 Gemini 等服务配置；历史继续追加到 Manggo `HistoryStore`。
- 原安装文件不被修改。构建或机器码不匹配时拒绝初始化；卸载恢复入口字节并删除扩展 UI。

## 2. 实现结构

### 窗口工厂

`packages/native/src/multiwindows.cpp` 从已有窗口取得 `AppContext`，调用当前构建自己的窗口构造函数。每个新窗口获得独立对象名、`WA_DeleteOnClose` 和标题栏 `＋`。

当前构建布局：

| 项目 | 值 |
| --- | --- |
| `TranslationWindow` 大小 | `0x358` |
| 窗口内 `AppContext` 偏移 | `0x28` |
| 窗口构造 RVA | `0x278080` |
| 原生 allocator RVA | `0x45cd70` |
| 标题栏 / 置顶对象 | `resultTitleBar` / `resultPinButton` |
| 新按钮对象 | `multiWindowsAddButton` |

`＋` 点击和三个入口钩子共用同一个 `WindowFactory`，不存在各入口各自实现翻译的逻辑。

### 入口分发

| 入口 | 接管位置 | 原语义修改点 |
| --- | --- | --- |
| 输入翻译 | `0x284420` | 原方法会清空当前输入框；改为先创建窗口再调用原方法 |
| 划词翻译 | `0x284b30` | 在固定窗口显示识别文本前换成新窗口 |
| 截图翻译 | `0x284d40` | 在 `(QString, QPoint, QImage)` 最终窗口槽前换成新窗口 |

三个位置都使用 14 字节绝对跳转，并在卸载时恢复原字节。输入入口的跳板包含一条 RIP 相对调用，使用绝对地址重定位；划词和截图入口复制 15 字节原始前缀。所有初始化都在 Manggo GUI 线程执行。

输入热键仍由原 `QHotkey` 持有，信号最终进入上述接管点，不另注册一套全局热键，因此不会发生双重响应。配置界面修改热键后仍由原应用处理。

### 焦点组与原生失焦关闭

所有 `TranslationWindow` 被视为一个焦点组，包括原窗口和新增窗口。实现不修改全局“失焦关闭”配置，也不强制置顶任何窗口。

| 环节 | 当前构建位置 | 行为 |
| --- | --- | --- |
| 窗口事件 | `0x27ea00` | 原生 `WindowDeactivate` 处理后，为组内所有翻译窗口调用原生关闭调度 |
| 延迟调度 | `0x284200` | 复用原生约 120 ms 延迟回调；`window+0x246` 防止重复调度 |
| 延迟回调 | `0x27fa40` | 从真实函数入口接管；组内切换取消本次关闭，组外切换交回原主体 |

原应用会跳过置顶来源窗口的调度，因此只在最后一个活动窗口上等待回调是不够的：置顶的最后活动窗口会把未置顶同伴留在屏幕上。事件入口的全组调度覆盖这个情况。

回调接管同时检查 `QApplication::activeWindow()` 和 Windows `GetForegroundWindow()`，避免跨应用切换时 Qt 活动指针尚未更新而误判为组内。组内取消时同步清除 `window+0x246`，保证下一次真正离开窗口组仍能调度。

自定义跳板重建 `action==0`、`action==1` 和其他动作的分支，普通 C++ detour 可以在平衡栈上返回。组外路径仍由原主体逐窗口检查失焦设置（`window+0x249` 及原配置）、置顶（`window+0x245`）、活动状态与 popup/modal；显式关闭按钮不经过该失焦回调。

### 加载器

`packages/loader/src/main.cpp` 支持附加到已运行进程或启动 Manggo 后附加。冷启动时有界等待 `TranslationWindow` 构造完成；失败时卸载 DLL。成功后加载器退出，扩展仅随 Manggo 进程驻留。`--unload` 调用原生卸载导出并释放模块。

没有开机启动、服务、计划任务或安装文件改写。

## 3. 真机验证记录

验证环境为本机 Manggo Windows x64 构建：PE timestamp `0x6ace6168`、SizeOfImage `0x1936000`、Qt 6.11.1。以下 RVA 只适用于这个构建。

| 验证项 | 结果与证据边界 |
| --- | --- |
| 标题栏与窗口工厂 | `＋` 位于关闭按钮左侧，可反复创建可见原生窗口；点击后原窗口保持可见 |
| 输入翻译 | 连续原生入口和真实 `QHotkey activated` 均创建新窗口，旧窗口草稿不变，一次信号只创建一个窗口 |
| 划词翻译 | 合成测试文本创建独立窗口，新增 `selection-translation` 历史，provider 元数据为原配置 Gemini |
| 截图翻译 | 合成文本与 96×64 非空 `QImage` 通过真实最终槽创建窗口，文本和图像均保留，新增 `screenshot-translation` 历史 |
| 历史隔离 | 两个输入窗口生成不同 UUID 的 `input-translation` 记录，无同 ID 覆盖 |
| 并行流式回调 | 两个窗口各有一个进行中的 `TranslationRun`，分别接收自己的流式结果，完成后请求对象均释放 |
| 组内焦点切换 | 原窗口→新增、新增→新增、新增→原窗口均保留其他输入窗口；最终手动回归通过 |
| 跨应用失焦与置顶 | 三窗口仅一个置顶的场景下，真实切到其他应用后未置顶窗口隐藏、置顶窗口保留；手动回归通过 |
| 独立语言方向 | 原窗口设置简体中文→英语、新增窗口设置英语→简体中文，互不影响，中间窗口保持原值 |
| 独立置顶 | 各窗口可分别置顶和取消置顶，状态互不影响；最终手动回归通过 |
| 关闭 | 普通关闭和进行中关闭均成功；关闭一个窗口后另一个窗口与主进程保持正常 |
| 卸载 | 五个钩子恢复、扩展窗口和按钮删除、DLL 模块释放，主进程响应正常 |
| 重启与加载 | 普通重启后无任何探针或扩展模块；加载器可附加、卸载并完成冷启动注入 |

所有合成测试历史随后通过 Manggo 自己的单条删除函数 `0x129290` 按明确 ID 删除；该函数同时处理关联图片和原生变更信号。复查副本为 0 条匹配记录，未直接改写原始数据库。最终回归后临时测试驱动均已卸载，正式扩展保留运行。

## 4. 尚未验证或实现

- 英汉词典等词典服务的专项调用与结果验证；已通过的是原 Gemini 翻译管线。
- provider 选择及更多语言组合的全矩阵测试；当前只验收了上述两种相反方向和置顶组合。
- 划词复制／替换、截图翻译并复制等变体的逐项真机验收；共用分发点已定位，但不能把静态推断当作逐项验证。
- 其他 Manggo 版本的 RVA、ABI、机器码和布局适配。
- 正式安装包、自动升级和发行签名。
- Manggo 官方插件 API 无法加载该原生 DLL；当前加载器是独立原型，不应包装成 `.mplugin`。安装校验是否触发模块导入仍是未实验假设，详见 `docs/manggo-plugin-development.md`。

前期 Electron 与 action 代码已移至 `legacy/electron-probe/`，不参与正式构建，不承担翻译、provider 配置或历史存储。
